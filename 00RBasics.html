Part 1. Quarto 문서 다루기

Quarto란?

이 워크숍의 실습 시간에 사용할 Quarto는 설명글, 코드, 분석 결과를 하나의 문서 안에서 함께 작성하고 렌더링할 수 있는 문서 작성 도구입니다. R을 이용한 데이터 분석뿐 아니라 Python, Julia 등 여러 언어를 지원하며, 하나의 원본 문서에서 HTML, PDF, Word, 슬라이드 등 다양한 형식으로 출력할 수 있습니다. Quarto 문서의 파일 확장자는 .qmd입니다. 이 실습에서는 .qmd 파일 안에서 설명을 읽고, 직접 R 코드를 작성하고 실행하면서 결과를 확인합니다.

Quarto 문서(.qmd)는 크게 세 가지 요소로 이루어집니다.

YAML 머리말은 문서 맨 위에 --- 세 개로 감싸인 부분입니다. 제목, 저자, 출력 형식처럼 문서 전체에 적용되는 설정을 작성합니다. 이 문서의 맨 위를 열어 보면 format: html 아래에 목차를 표시하도록 설정하는 toc: true가 있습니다. 실습에서는 YAML을 직접 수정할 필요가 거의 없습니다. 제공된 설정을 그대로 사용하면 됩니다.

마크다운 본문은 설명을 작성하는 부분입니다. 지금 읽고 계신 이 문단도 마크다운 본문에 해당합니다. 제목, 목록, 강조, 링크 등을 간단한 기호를 이용해 작성할 수 있습니다. 마크다운의 기본 문법은 Task 1에서 직접 작성해 보면서 살펴보겠습니다.

코드 블록은 세 개의 백틱과 {r}로 시작하고 다시 백틱 세 개로 끝나는 부분입니다. 코드 블록 안에 작성한 R 코드를 실행하면 그 결과를 같은 문서 안에서 바로 확인할 수 있습니다.

이처럼 설명, 분석 코드, 분석 결과를 하나의 문서 안에 함께 기록할 수 있다는 점이 Quarto의 중요한 장점입니다. 코드와 결과가 분리되지 않기 때문에 분석 과정을 나중에 다시 확인하거나 다른 사람과 공유하기도 쉽습니다.

또한 Quarto에서는 R뿐 아니라 Python, Julia 등 여러 언어를 사용할 수 있습니다. 코드 블록을 시작할 때 중괄호 안의 언어를 바꾸면 됩니다.

Task 1. 마크다운 문법

아래는 본 실습 자료에서 쓰이는 마크다운 문법입니다. 빈칸을 채운 뒤 이 블록의 내용을 복사해 본문에 붙여넣고 렌더링해 결과를 확인해 보세요.

Part 2. R의 기본 문법

할당 연산자 <-

R에서 값을 저장할 때는 화살표 <-를 씁니다. 오른쪽의 값을 왼쪽 이름에 넣으라는 뜻입니다.

x <- 10
x
[1] 10

x <- 10을 실행해도 화면에는 아무것도 나오지 않습니다. 저장만 하고 출력은 하지 않기 때문입니다. 값을 보려면 이름만 따로 실행하면 됩니다.

=도 같은 일을 하지만, 관례상 저장에는 <-를, 함수의 인수를 지정할 때는 =를 씁니다. 아래에서 mean(x, na.rm = TRUE)의 =가 그 경우입니다. 두 기호를 구분해 두면 코드를 읽을 때 무엇이 저장이고 무엇이 인수 지정인지 구분이 쉽습니다.

RStudio와 Positron에서는 Alt + -(Mac은 Option + -)를 누르면 <-가 공백과 함께 입력됩니다. 매번 세 타를 치지 않아도 됩니다.


파이프 연산자 |>

파이프는 앞의 결과를 뒤 함수의 첫 번째 인수로 넘기라는 뜻입니다. 예를 들어, 아래 두 줄은 완전히 같은 코드입니다.

v <- c(3, 1, 4, 1, 5)

mean(v)
[1] 2.8
v |> mean()
[1] 2.8

값 하나를 넘길 때는 차이가 없어 보이지만, 단계가 여러 개일 때는 순서와 가독성이 달라집니다. 파이프가 없으면 함수가 안쪽부터 중첩되어 읽는 순서와 실행 순서가 반대가 됩니다. 본 실습의 데이터 정리 코드가 대부분 이 형태입니다.

# 파이프 없이: 안쪽에서 바깥쪽으로 읽어야 합니다
round(sqrt(mean(v)), 2)

# 파이프로: 왼쪽에서 오른쪽으로 순서대로 읽힙니다
v |> mean() |> sqrt() |> round(2)

참고로 |>는 R 4.1부터 기본으로 들어간 연산자입니다. 예전 자료에서 보이는 %>%도 파이프로 하는 일은 거의 같지만 magrittr 패키지를 불러와야 사용할 수 있습니다.

파이프도 단축키가 있습니다. Ctrl + Shift + M(Mac은 Cmd + Shift + M)입니다.


Task 2. 객체와 자료형

R에서 값을 저장할 때는 화살표 <-를 씁니다. 등호도 동작하지만 관례상 화살표를 쓰고, 등호는 함수의 인수를 지정할 때 씁니다. 다음의 안내에 따라 객체에 값을 저장하고, 객체의 속성을 확인하는 코드를 작성해 보세요.

  • x: 10을 저장합니다.
  • v: 여러 값을 묶을 때는 c()를 씁니다. c(3, 1, 4, 1, 5)를 저장합니다.
  • s: 문자는 따옴표로 감쌉니다. "KAPAE"를 저장합니다.
  • b: 참거짓은 TRUE와 FALSE입니다. 따옴표를 붙이지 않습니다.
  • class()로 자료형을, length()로 길이를 확인합니다.

R에서 데이터를 다룰 때 가장 기본적으로 사용하는 자료구조 중 하나가 데이터 프레임(data frame)입니다. 데이터 프레임은 엑셀의 표와 같은 행과 열로 구성된 2차원 테이블이라고 생각하면 됩니다. 각 열에는 서로 다른 형식의 값이 들어갈 수 있습니다. 예를 들어 한 열은 숫자, 다른 열은 텍스트로 구성할 수 있습니다.

Part 7. 문서 렌더링

렌더링(rendering)이란?

지금까지는 코드 블록을 하나씩 실행하면서 결과를 확인했습니다. 렌더링(rendering)은 .qmd 파일 전체를 위에서부터 한 번에 실행하고, 코드의 실행 결과를 본문의 글과 함께 엮어 하나의 HTML 문서로 만드는 작업입니다.

여러분에게 제공된 실습 파일 중 .html 파일은 .qmd 파일을 렌더링한 결과물입니다. 마크다운에서 정한 형식에 따라 글과 코드를 작성하면 Quarto가 이를 정리하여 지금 보고 계신 것과 같은 보기 좋은 문서를 간편하게 만들어 줍니다.

렌더링은 대략 다음과 같은 과정을 거칩니다.

  1. knitr가 R 코드 블록을 위에서부터 순서대로 실행하고 결과와 그림을 수집합니다.
  2. 코드 실행 결과를 본문의 마크다운과 결합합니다.
  3. Quarto가 이를 HTML로 변환하고 YAML에서 지정한 목차와 스타일 등을 적용합니다.

지금 보고 계신 이 문서도 같은 과정을 거쳐 만들어졌습니다.

데이터 분석 결과를 공유하는 아주 쉬운 방법

Quarto에서는 분석 코드, 실행 결과, 결과에 대한 설명을 하나의 문서에서 함께 관리할 수 있습니다. 데이터나 분석 코드가 바뀌더라도 문서를 다시 렌더링하면 표와 그림을 포함한 결과가 모두 함께 갱신됩니다. 분석 결과를 따로 복사해서 Word 등에 옮겨 붙이는 과정이 줄어들고, 이전 분석 결과를 실수로 그대로 남겨 두는 문제도 방지할 수 있습니다.

또한 문서 전체를 처음부터 끝까지 실행해 보는 것은 분석의 재현성을 확인하는 좋은 방법입니다. 콘솔에서 코드 블록을 하나씩 실행하다 보면 현재 R 세션에 우연히 남아 있는 객체에 의존할 수 있습니다. 반면 새로운 세션에서 문서를 처음부터 렌더링했을 때도 정상적으로 실행된다면, 필요한 코드와 객체가 문서 안에서 올바른 순서로 만들어지고 있는지 확인할 수 있습니다.

렌더링하는 방법

가장 간단한 방법은 편집기 상단의 Render 또는 Preview 버튼을 사용하는 것입니다. RStudio나 Positron에서 해당 버튼을 누르면 현재 .qmd 문서를 렌더링할 수 있습니다.

단축키를 사용할 수도 있습니다.

  • Windows: Ctrl + Shift + K
  • Mac: Cmd + Shift + K

지금 한 번 단축키를 눌러 이 문서를 직접 렌더링해 보세요.

터미널에서도 렌더링할 수 있습니다. 터미널을 열고 .qmd 파일이 있는 폴더에서 다음 명령어를 실행합니다.

quarto render 00RBasics_sol.qmd

렌더링이 완료되면 같은 폴더에 00RBasics_sol.html이 만들어집니다. 이 파일을 브라우저에서 열면 렌더링된 문서를 확인할 수 있습니다.

R 콘솔에서 실행할 수도 있습니다.

quarto::quarto_render("00RBasics_sol.qmd")

렌더링이 실패할 때

렌더링 과정에서 오류가 발생하더라도 대부분 오류 메시지를 따라가면 원인을 찾을 수 있습니다.

첫 번째로 확인할 것은 완성되지 않은 코드입니다. 실습 파일의 학생용 코드 블록에는 _____와 같은 빈칸이 남아 있습니다. 이 상태로 실행하면 오류가 발생할 수 있으므로, 아직 완성하지 않은 코드 블록에는 #| eval: false를 붙여 렌더링할 때 실행되지 않도록 해 두었습니다. 빈칸을 모두 채운 뒤 이 옵션을 지우면 해당 코드 블록도 렌더링할 때 함께 실행됩니다.

result <- _____

두 번째로 확인할 것은 파일 경로입니다. 예를 들어 다음 코드는 현재 작업 위치에서 ohie_all6m.rds라는 파일을 찾습니다.

ohie <- readRDS("ohie_all6m.rds")

파일이 예상한 위치에 없다면 렌더링 과정에서 파일을 찾지 못했다는 오류가 발생합니다. 실습에서는 경로 문제를 줄이기 위해 필요한 데이터 파일을 안내된 위치에 두세요.

세 번째로 확인할 것은 앞선 코드 블록에서 만들어지는 객체입니다. 예를 들어 뒤쪽 코드에서 model_df를 사용한다면 그보다 앞선 코드 블록에서 model_df가 먼저 만들어져야 합니다. 콘솔에서 이전에 만들어 둔 객체에만 의존하고 문서 안에는 해당 객체를 만드는 코드가 없다면 렌더링 과정에서 다음과 같은 오류가 발생합니다.

object 'model_df' not found

렌더링 오류 메시지에는 일반적으로 문제가 발생한 코드 블록이나 파일의 위치가 함께 표시됩니다. 오류가 발생하면 먼저 어떤 코드 블록에서 멈췄는지 확인하고, 해당 코드 블록과 바로 앞의 코드를 점검하세요.
